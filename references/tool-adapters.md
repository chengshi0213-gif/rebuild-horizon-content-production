# 视频技术执行适配

工具路线是执行选择，不是第二个创作入口。先读工程文件、锁文件和已安装 CLI/API 的实际帮助。只有适配器真正可用时才执行，不以插件缓存存在证明工具已安装。当前宿主工具说明优先于历史资料。

## Remotion

用于 React/代码动画、标题、解说、字幕与可复用视频组件。沿用现有工程、Composition、props、fps、durationInFrames 和打包脚本；新项目若需新增依赖按用户授权办理。

- 动画应由当前帧和声明参数确定，避免 Date.now、未固定随机、交互/墙钟计时导致渲染漂移。
- 序列、转场、音频与字幕使用同一时基，保留完整片长及黑场/静默的意图；相邻区间遵守项目帧口径。
- 先看内容最密集的静态布局，再检查进入、退出和转场；字体、素材加载、字幕避让需真实预览。
- 现有脚本适用时运行 lint/typecheck/build；先短段或关键帧，再完整输出。调用 CLI 前核对本机版本与帮助，不盲用 `@latest`。
- 输出视频是用户要求时执行渲染，不用旧来源“只能预览”的通用模板阻断。没有渲染就不声称成片。

## HyperFrames / GSAP

用于 HTML 视频构图、字幕、音频响应与动画叠加。先核对当前项目的 data 属性、composition 时长与 timeline 契约，再写代码。

- 先在元素完整可见的状态建立布局，检查拥挤、文字宽高和安全区，再添加入场/出场。
- 基于可 seek 的时间线；检查从任意中间时刻定位是否得到正确状态，不依赖只播放一次的副作用。
- 明确嵌套 composition 的局部/全局时间，音频/视频片段裁切与可视区间一致。
- 沿用用户/项目已有视觉定义；缺细节可给合理候选，不因没有 DESIGN.md 强制问三题。
- 动效应支持信息层次，逐字高亮、频闪、glitch、音频反应均不是默认必加。

## 图像、声音、视频生成与剪辑

图像使用当前宿主图像工具；视频/声音使用已授权可用工具或现有本地工程。先检查输入范围、版本、文件、支持的控制与输出；不盲装第三方 skill、API 客户端、模型或节点。

FFmpeg/ffprobe 如已存在，可用于元数据、裁切、混合、字幕与导出；先看命令与现有项目脚本。使用精确时间基准，素材来源和编码假设明确。片段拼接、字幕和压缩后再次检查真实成片。

通用图片、语音、转录、文档、网页/浏览器工具继续作为执行能力保留，不需要为本技能改动其独立用途。
