# 声音、对白与时间

时间是对白、动作、反应和观众理解共同使用的资源。以当前 [对白交换](dialogue.md) 和镜头稿为依据，用真实声音和预演校准；只改时间时不重新开发人物。没有统一“每秒几个汉字”的表演标准。

## 五种时间不要混写

1. **发声时间**：实际音节和声音占用，不含被明确排除的静默。
2. **一条 take 的跨度**：从指定入口到出口，可含犹豫、呼吸、强调和内部停顿。记录裁切口径。
3. **场次剪辑跨度**：最终时间轴末端减开端，含有意的沉默、等待、空镜、识别与余韵。
4. **占用并集**：某些声音/动作区间在时间轴上的并集；它不等于场次片长，也不能相加得到并发总时长。
5. **生成长度**：剪辑采用长度加需要生成的前后余量（handles）；预留余量不自动进入成片。

`speech rate` 若已含静默，不再另加同一停顿。`articulation rate` 排除静默，才可按一致口径补静默；呼吸、重音延长和停顿也可能重合，不能重复相加。源音频采样长度含头尾空白时，不等于可用发声时长。

无对白区间仍可能有移动、操作、环境声或观众识别任务，不能直接命名为“沉默”。长停留要有可观看的内容与节奏依据，不能为了凑片长均摊到镜头尾部。短句也可能因复杂动作而占很长一段；用完整片段检验，不能只拿字数估算反推表演。

## A0–A3：证据成熟度

| 层级 | 可以交什么 | 不能冒充什么 |
| --- | --- | --- |
| A0 剧本估算 | 时长区间、假设、语义组块、候选时间轴 | 真人/TTS 试读、固定口型、实测通过 |
| A1 试读与初排 | 可访问的录音版本、实际读法、裁切和测量方法、镜头时间分配 | 仅凭文本升级；画面节奏已经成立 |
| A2 连续音画预演 | 真实播放的 Animatic、采用 Cue/take、切点、同步点、观察和修订记录 | 静态表格或图片列表就是预演 |
| A3 交付快照 | 冻结上述实际来源与时间版本，列出未制作项 | 一定完成了成片、声音母版或口型验证 |

A3 另保留 `validated_through: A0/A1/A2`，允许交估算蓝图但不得洗成实测。无对白项目可用动作/音效时间依据，缺对白录音无需假造。

## 试读怎么变成决定

将原文与实际 spoken text 分开：数字/单位/缩写展开、多音字、儿化、停顿意图经选定进入同一 Cue。给每条稳定 ID，跨镜引用它，不复制成第二句。

在确有声音工具且当前请求包含声音试制时，生成或采集录音；否则交 A0 和待试读范围。优先检查长句、转义处、笑点、抢话和视觉竞争处。必要时比较：

- 自然表演版：符合人物当前状态。
- 编辑版：保持意义、调整冗余与动作分配。
- 最低可懂版：只探测极限，不默认作为选版。

记录 take、演员/工具、文本版本、音频路径、采样率、测量起止、实际观察。需要听感判断就实际听；仅分析波形只能报告波形/时长。时间戳精确不意味着表演精确。

## 同步、抢话与跨镜

同一场用同一时基；帧区间用 `[in,out)`，相邻帧不重叠。fps 可为有理数（如 24000/1001），别把显示舍入值当精确时基。项目使用毫秒时明确转换和取整策略。

每条 Cue 标记语义落点。听者可以在句中理解并反应，也可能先看到动作再听到词；反应起点不能早于其信息依据。反应不必等整句结束。

快速接话（几乎无间隙）、打断（前句在指定位置被截断）、同时说话（区间重叠）分别设计。重叠标明听觉主次；多人齐声可有意同步。跨镜声桥保留原 Cue 和完整场次时间，剪辑镜头只引用相交部分。

## 超时返修

先找原因：重复解释、信息太多、视觉与语言争抢、反应时间漏算、读法展开、实际发音卡顿、生成约束还是镜头分配失衡。

按原因选最小可行改动：消除重复计时、将可同时发生的动作并排、调整切点/声桥，或回剧本删改冗余与动作结构。不是依次试遍所有方法。用户锁了时长就优先在允许范围重写，锁了台词就提调整时长或视觉安排的方案。若两者都固定且无法兼容，明确指出冲突。统一倍速不能成为默认解法。

## 可检查 JSON（需要机器核对时才使用）

```json
{
  "fps": {"num": 24, "den": 1},
  "duration_frames": 240,
  "maturity": "A0",
  "validated_through": "A0",
  "cues": [
    {"id": "D01", "speaker": "阿岚", "text": "先别关灯。", "spoken_text": "先别关灯。", "in": 24, "out": 66, "timing_basis": "estimate"}
  ],
  "shots": [
    {"id": "S01", "in": 0, "out": 48, "cue_ids": ["D01"]},
    {"id": "S02", "in": 48, "out": 240, "cue_ids": ["D01"]}
  ],
  "events": [{"id": "E01", "in": 72, "out": 120, "description": "听者松开墙上开关"}],
  "handles": {"head_frames": 12, "tail_frames": 12}
}
```

A1/A2 的对白 Cue 使用 `timing_basis: measured`、`audio_path`、`measurement_note`。A2 另有 `animatic_path` 和 `review_note`。路径相对 JSON 所在目录或绝对路径。工具只验证这些证据文件存在，不能证明它们内容正确或已经被听看。

`python scripts/timing_check.py 文件.json` 检查：唯一 ID；合法整数帧/正帧率；场次范围；镜头连续覆盖；Cue 引用实际相交且跨镜不丢失；成熟度声明和证据文件；生成余量。报告片长与各轨道占用并集，保留有意空档。不因 A0 写了精确候选帧数就宣称实测。
